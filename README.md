# OnlyTab —— 极简标签页

一个**极简、低占用**的浏览器新标签页 / 导航起始页，使用 **Docker** 一键部署。
参考 [mtab](https://github.com/tsxcw/mtab) 的思路，但砍掉所有重依赖，做到：

- **零运行时依赖**：后端是单个 `server.js`（纯 Node `http`，不装任何 npm 包），镜像小、内存占用极低。
- **仅两个页面**：首页（`/`）与管理页（`/admin`）。
- **可在管理页自定义**：标签、搜索引擎、天气城市、站点版权 / ICP 备案 / 网安备案、背景。
- **数据持久化**：配置存于 `data/config.json`，上传图标/背景存于 `data/uploads/`，用卷挂载即可永久保存。

---

## 功能一览

### 首页
- **时钟**：时分秒 + 日期 + 星期（取浏览器本地时间）。
- **搜索框**：默认百度，可下拉切换引擎（管理页可增删与自定义）。
- **天气组件**：默认按访问者 IP 定位（国内 IP 探针 + Open-Meteo，免费无需密钥），管理页可改为指定城市，或切换为国内「和风天气」源（支持新版 **JWT / Ed25519** 鉴权，也可兼容旧版 Key）；展示当前温度、最高/最低及未来 5 天预报。
- **日历组件**：当月日历 + 今日高亮 + 农历。
- **标签网格**：每行可设多个，显示图标（URL / 本地上传 / 预设图标）、名称，点击新标签打开目标网址。
- **底部**：版权、ICP 备案号、网安备案号（均可自定义，备案号自动链接到官方查询页）。
- **背景**：内置默认渐变；管理页提供 **5 套预设渐变**、**两个十六进制色自定义渐变**、以及 3 张公开图床背景图，也可上传 / 填 URL。

## 快速开始

### 方式一：Docker（推荐）

```bash
# 构建并启动
docker compose up -d --build

# 访问
# 首页： http://localhost:3000/
# 管理页： http://localhost:3000/admin
```

停止：`docker compose down`
查看日志：`docker compose logs -f`

> 首次启动会在 `./data` 生成 `config.json` 与 `uploads/`，配置与上传文件都会保存在这里，重启不丢。

### 方式二：直接运行 Node（无需 Docker）

```bash
node server.js
# 或
npm start
# 默认端口 3000，可用环境变量覆盖
PORT=8080 node server.js
```

要求 Node >= 16。

## 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `3000` | 服务端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATA_DIR` | `./data` | 配置与上传文件目录 |
| `ADMIN_USER` | `admin` | 管理员用户名（选填，默认 `admin`） |
| `ADMIN_PASSWORD` | `OnlyTab` | 管理员密码（选填，默认 `OnlyTab`） |

管理页（登录账号）默认 `admin` / `OnlyTab`，**鉴权默认开启**，访问 `/admin` 与保存配置都需要登录。这两个环境变量为**选填**：不填则使用默认值，且可在管理页「登录账号」中随时修改（修改后会强制重新登录）。如要用环境变量预设，在 `docker-compose.yml` 中取消注释并修改即可。

```bash
# docker-compose.yml 中取消注释并修改：
environment:
  - ADMIN_USER=admin
  - ADMIN_PASSWORD=OnlyTab
```

## 管理页说明

进入 `/admin`（需登录，默认 `admin` / `OnlyTab`）：

1. **站点与底部信息**：标题、背景（URL 或上传）、版权、ICP 备案号、网安备案号。
2. **登录账号**：在此修改管理员用户名 / 密码（密码留空则仅改用户名，填写需至少 6 位）。修改成功后所有会话失效，需重新登录。
3. **搜索引擎**：设置默认引擎；引擎列表里搜索链接用 `{q}` 作为关键词占位符，例如 `https://www.baidu.com/s?wd={q}`。
4. **天气**：`自动`（按访问者 IP，国内源定位）或 `指定城市`（填城市名，如“杭州”）；数据源可在 `Open-Meteo`（默认，免密钥）与「和风天气」（国内源）间切换。和风天气支持两种鉴权：
   - **JWT（推荐，新版）**：点「生成密钥对」自动在服务端生成 **Ed25519** 密钥（私钥仅存服务端），把返回的公钥上传到和风控制台 → 项目管理 → 凭据（选 JSON Web Token），再填凭据 ID（kid）与项目 ID（sub）。
   - **旧版 API KEY**：直接填 Dev Key（仍可用）。
5. **样式设置**：每行标签个数、图标大小、字体粗细、是否显示读秒；新增「时钟/日期」的字号、粗细、颜色（六位十六进制），以及「标签名称」颜色（六位十六进制）。
6. **背景设置**：模式可选默认渐变 / 预设渐变 / 自定义颜色 / 背景图片；提供 5 套预设渐变色板、两个十六进制颜色自定义、3 张公开图床背景图，也可上传或填 URL。
7. **导航标签**：紧凑多列编辑（一行显示多个），增 / 删 / 上移 / 下移；图标可填 URL、上传本地图片，或点「预设图标」从 **xg-icons-hub** 选取 20 个内置图标（经服务端代理，规避图床防盗链）。
8. 点击「保存」即时生效。

## 关于备案（ICP / 网安）

本站为纯静态展示 + 轻量配置接口，内容合规、结构简单，适合作为已备案域名下的子站或独立站点部署。
底部备案号在管理页填写后自动展示并链接到官方查询页：

- ICP 备案：`https://beian.miit.gov.cn`
- 公安网安备案：`https://www.beian.gov.cn`

> 部署到国内服务器前，请先在接入商完成域名 ICP 备案与公安备案，并将备案号填入管理页。

## 天气与定位（国内源）

天气与 IP 定位全部经由**服务端代理**（`/api/location`、`/api/weather`），由服务器去请求数据源，浏览器只与同源后端通信，既避免跨域（CORS）问题，也便于在国内网络环境使用：

- **IP 探针（国内源）**：依次尝试 `ip.cn`、`vore.top`，最后回退 `ipapi.co`。
- **天气源**：
  - 默认 `Open-Meteo`（国际源，免密钥，国内可直连），开箱即用；
  - 可在管理页切换为「**和风天气**」（国内源），填入免费的 Dev Key 即可获得更准确的国内天气。
  - **和风 JWT（新版默认鉴权）**：和风现已主推 JWT（`Ed25519` / `EdDSA` 签名）。在管理页天气卡片点「生成密钥对」即可由服务端生成密钥对——私钥自动存入服务端配置（不会下发给浏览器），公钥复制后到和风控制台「项目管理 → 凭据」添加一条「JSON Web Token」凭据并粘贴公钥，再把该凭据的 **ID（kid）** 与 **项目 ID（sub）** 填回管理页。配置完整后请求自动带上 `Authorization: Bearer <JWT>`。旧版 `?key=` 方式仍兼容。

> 服务端内置 30 分钟天气缓存与 1 小时定位缓存，降低对外请求频率。
> 和风 Key / 私钥仅存于服务端配置，不会下发给浏览器。

若服务器位于完全无外网的环境，建议在管理页将天气改为「指定城市」并在可联网时获取；如仍失败，首页天气区会显示「获取失败」，不影响其它功能。

## 样式设置

管理页「样式设置」可调整：

- 每行标签个数（横排）、图标大小、标签名称字体粗细、是否显示读秒；
- **时钟 / 日期**：字号（px）、粗细、颜色（六位十六进制，如 `#ffffff`）；
- **标签名称**颜色（六位十六进制）。

修改即时生效，作用于首页。首页三大区域（时钟/搜索、天气日历、标签网格）宽度统一对齐，视觉更整齐。

## 背景设置

管理页「站点与底部信息 → 背景设置」提供四种模式：

- **默认渐变**：使用系统内置渐变；
- **预设渐变**：5 套精选渐变方案（深蓝 / 紫粉 / 日落 / 薄荷 / 暗夜），一键切换；
- **自定义颜色**：两个十六进制颜色组成线性渐变（两色相同即纯色）；
- **背景图片**：3 张公开图床（picsum）预设图，或上传 / 填 URL。

## 预设图标

管理页编辑标签时，点「预设图标」可从内置的 **xg-icons-hub**（部署在局域网 `http://192.168.9.126:28080`）选取 20 个常用图标（百度、Google、GitHub、B 站、YouTube、ChatGPT、DeepSeek、Claude、Gemini、Notion、Telegram、豆瓣、百度地图、CloudFlare、Docker、HomeAssistant、Vaultwarden、天气、immich、Netflix）。图标由 OnlyTab 服务端 `/api/icon` 代理拉取，规避图床防盗链；若你的 hub 地址不同，改 `server.js` 里的 `iconHub` 默认值即可。

## 已发布镜像（v0.1）

本项目已接入 GitHub Actions：打 `v*` 标签或发布 Release 即自动构建并推送镜像，无需本地 Docker。

- **GitHub Container Registry**：`ghcr.io/fromeverywhere/onlytab:0.1`（同时打 `:latest`）
- **Docker Hub**：`fromeverywhere/onlytab:0.1`（同时打 `:latest`）

拉取运行：

```bash
docker pull fromeverywhere/onlytab:0.1
docker run -d -p 3000:3000 --name onlytab fromeverywhere/onlytab:0.1
```

> CI 通过 GitHub Secrets（`DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN`）推送 Docker Hub，凭据不入库、不明文。

### 绿联（UGREEN）NAS 构建示例

源码已构建运行于绿联 NAS，端口映射 `19321`：

```bash
docker run -d --name onlytab -p 19321:3000 --restart unless-stopped fromeverywhere/onlytab:0.1
# 浏览器访问 http://<绿联IP>:19321/
```

也可在 NAS 内从源码 `docker build -t onlytab:0.1 .` 后同上运行。

## 资源占用

单个 Node 进程，无数据库、无外部中间件；空闲内存通常 **20~40 MB**，CPU 几乎为零。非常适合跑在 1C1G 甚至更小的轻量服务器 / NAS / 内网机。
