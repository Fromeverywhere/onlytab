# OnlyTab —— 极简标签页

一个**极简、低占用**的浏览器新标签页 / 导航起始页，使用 **Docker** 一键部署。
参考 [mtab](https://github.com/tsxcw/mtab) 的思路，但砍掉所有重依赖，做到：

- **零运行时依赖**：后端是单个 `server.js`（纯 Node `http`，不装任何 npm 包），镜像小、内存占用极低。
- **仅两个页面**：首页（`/`）与管理页（`/admin`）。
- **可在管理页自定义**：标签、搜索引擎、天气城市、站点版权 / ICP 备案 / 网安备案、背景。
- **数据持久化**：配置存于 `data/config.json`，上传图标/背景存于 `data/uploads/`，用卷挂载即可永久保存。

---

## 功能一览

### 首页
- **时钟**：时分秒 + 日期 + 星期（取浏览器本地时间）；字号、粗细、颜色同时作用于时钟与日期两行。
- **搜索框**：默认百度，可下拉切换引擎（管理页可增删与自定义）。
- **天气组件**：三选一数据源 —— `Open-Meteo`（国际源，免密钥）、`中国天气网`（国内源，免登录免密钥，推荐）、`和风天气`（国内源，仅支持新版 **JWT / Ed25519**）；展示当前温度、天气、最高/最低及未来 5 天预报。IP 定位不可用时自动用配置城市或默认城市兜底，天气不会空白。
- **日历组件**：当月日历 + 今日高亮 + 农历。
- **混排面板（v0.2）**：天气、日历与所有标签统一排在同一个网格里，**可直接拖动混排排序**（鼠标拖动 / 手机长按 220ms 后拖动），顺序自动保存到服务端；小组件与标签可任意穿插。
- **标签**：每行个数可设，显示图标（URL / 本地上传 / 本地预设图标）与名称；**只有图标和名称两处可点**，容器没有背景、边框和焦点框，选中不会出现透明长方形框。
- **底部**：版权、ICP 备案号、网安备案号（均可自定义，备案号自动链接到官方查询页）。
- **背景**：内置默认渐变；管理页「背景」子页面提供 **5 套预设渐变**、**两个十六进制色自定义渐变**、以及 3 张公开图床背景图，也可上传 / 填 URL；图片模式下可用**滑条 + 数值框**调节毛玻璃模糊强度。

## 快速开始

### 方式一：Docker（推荐）

```bash
# 构建并启动
docker compose up -d --build

# 访问
# 首页： http://localhost:3000/
# 管理页： http://localhost:3000/admin
```

停止：`docker compose down`
查看日志：`docker compose logs -f`

> 首次启动会在 `./data` 生成 `config.json` 与 `uploads/`，配置与上传文件都会保存在这里，重启不丢。

### 方式二：直接运行 Node（无需 Docker）

```bash
node server.js
# 或
npm start
# 默认端口 3000，可用环境变量覆盖
PORT=8080 node server.js
```

要求 Node >= 16。

## 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `3000` | 服务端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATA_DIR` | `./data` | 配置与上传文件目录 |
| `ADMIN_USER` | `admin` | 管理员用户名（选填，默认 `admin`） |
| `ADMIN_PASSWORD` | `OnlyTab` | 管理员密码（选填，默认 `OnlyTab`） |

管理页（登录账号）默认 `admin` / `OnlyTab`，**鉴权默认开启**，访问 `/admin` 与保存配置都需要登录。这两个环境变量为**选填**：不填则使用默认值，且可在管理页「登录账号」中随时修改（修改后会强制重新登录）。如要用环境变量预设，在 `docker-compose.yml` 中取消注释并修改即可。

```bash
# docker-compose.yml 中取消注释并修改：
environment:
  - ADMIN_USER=admin
  - ADMIN_PASSWORD=OnlyTab
```

## 管理页说明（v0.2 子页面）

进入 `/admin`（需登录，默认 `admin` / `OnlyTab`）。管理页已拆成 6 个子页面，顶部导航一键切换，不再挤在一页：

1. **站点与样式**：站点标题、版权、ICP / 网安备案号；桌面端每行标签个数、图标大小、标签名称粗细、是否显示读秒、时钟/日期字号与粗细与颜色（六位十六进制）、标签名称颜色（带实时预览）；独立的「📱 手机端适配」区（每行个数、图标大小、时钟字号、标签名称字号、最多显示标签数）。
2. **背景**：四种背景模式卡片（默认渐变 / 预设渐变 / 自定义颜色 / 背景图片）。**选定一种模式后，其余模式的详细设置自动置灰且不可编辑**。预设 5 套渐变色板、两个十六进制色自定义、3 张公开图床图；图片模式可点击或拖拽上传（重做的上传区），并有毛玻璃滑条 + 数值输入框。
3. **搜索引擎**：设置默认引擎；搜索链接用 `{q}` 作为关键词占位符，例如 `https://www.baidu.com/s?wd={q}`。
4. **小组件**：天气数据源、定位方式与城市、和风 JWT 凭据与操作步骤；首页混排排序说明与「重置排序」。
5. **标签**：紧凑多列编辑（一行显示多个），增 / 删 / 上移 / 下移；图标可填 URL、上传，或点「预设图标」选取 20 个**本地内置**图标；并提供「同步首页排序」。
6. **登录账号**：修改管理员用户名 / 密码（密码留空则仅改用户名，填写需至少 6 位）；修改成功后所有会话失效，需重新登录。

点击「保存」即时生效（写入 `data/config.json`）。首页的拖动排序默认无需登录即可保存（如需关闭，把 `layout.publicReorder` 设为 `false`）。

## 天气与定位（国内源）

天气与 IP 定位全部经由**服务端代理**（`/api/location`、`/api/weather`），由服务器去请求数据源，浏览器只与同源后端通信，既避免跨域（CORS）问题，也便于在国内网络环境使用。

### 三个数据源

| 数据源 | 是否需要登录 / 密钥 | 说明 |
| --- | --- | --- |
| `Open-Meteo` | 否 | 国际源，按经纬度取数，开箱即用 |
| `中国天气网`（v0.2 新增，推荐） | **否** | 国内免登录免密钥；先用 `toy1.weather.com.cn/search` 查 9 位城市码，再从 `d1.weather.com.cn/weather_index` 解析实时天气与 5 天预报 |
| `和风天气` | 是（新版 JWT） | 国内源，**仅支持新版 JWT / Ed25519**；旧版 `?key=` API KEY 已在 v0.2 移除 |

**和风天气 JWT 操作步骤**（管理页「小组件 → 天气」内也附有说明）：

1. 登录和风天气控制台 → **项目管理** → 创建项目，记下**项目 ID**。
2. 在该项目下点 **凭据 → 添加凭据**，认证方式选 **JSON Web Token (JWT)**。
3. 在 OnlyTab 管理页点「**生成密钥对**」，服务端生成 Ed25519 密钥对；复制**公钥**粘贴到和风控制台的凭据里（私钥只留在服务端，不会下发浏览器）。
4. 复制该凭据的 **凭据 ID（kid）** 与 **项目 ID（sub）**，填回管理页并保存。
5. OnlyTab 用 `EdDSA` 签名生成 JWT，请求带 `Authorization: Bearer <JWT>`。若凭据未填完整，自动回退到中国天气网，天气不会空白。

> 服务端内置 30 分钟天气缓存与 1 小时定位缓存。和风私钥仅存于服务端配置，`/api/config` 会剔除账号、私钥与内部字段。

### 定位失败兜底（v0.2）

- IP 探针改为 **3 源并行**（`ip.cn` / `vore.top` / `ipapi.co`，单源 3 秒超时），取最快成功者，不再串行等待最坏 21 秒。
- 内网 / NAS 上 IP 定位常不可用：此时自动退回**管理页指定城市**，没填则用「北京」，并标记 `degraded: true`。
- 没有经纬度时不会拿 `(0,0)` 去查赤道天气，而是自动切到按城市取数的国内源；前端即使定位接口报错也会继续用城市请求天气。
- 因此无外网或定位失败时天气区仍可显示数据，只有所有天气源都不可用时才提示「获取失败」。

如需固定城市，在管理页把定位方式改为「指定城市」并填写城市名（如 `杭州`）。

## 样式设置

管理页「站点与样式」子页面可调整：

- 每行标签个数（横排）、图标大小、标签名称字体粗细、是否显示读秒；
- **时钟 / 日期**：字号（px）、粗细、颜色（六位十六进制，如 `#ffffff`），并有实时预览；
- **标签名称**颜色（六位十六进制）。

v0.2 修复了「时间字体太细」：`.date` 不再写死 `font-weight: 400` 和固定字号，而是与时钟一起跟随 `--time-weight` / `--time-size`；默认粗细由 `200` 一次性迁移到 `400`（旧配置自动升级）。首页的时钟/搜索、混排面板统一使用 `--content-w` 保持左右对齐。

## 首页混排与拖动排序（v0.2）

天气、日历与所有标签现在统一放在 `.board` 网格中，服务端用 `layout.order` 保存顺序（`w:weather` / `w:calendar` / `t:<标签id>`）：

- **桌面**：鼠标按住任意元素移动 7px 即进入拖动，会显示插入位置标记；松手后顺序写入 `POST /api/order`。
- **手机**：长按 220ms 后才进入拖动，避免与页面滚动、点击标签冲突。
- 拖动结束后会抑制一次点击，避免误打开标签；若服务端暂时不可达，顺序先存 `localStorage`，下次成功再同步。
- 标签容器本身没有背景、边框和焦点框，**只有图标与名称两个 `<a>` 可点击**，解决了选中时出现透明长方形框的问题。

## 手机端适配

首页在屏宽 ≤ 760px 时自动切换到手机布局，且与桌面端设置**相互独立**、互不影响：

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 手机端每行标签个数 | `4` | 替代桌面端的 8 列，可设 1–10 |
| 手机端图标大小 | `38px` | 独立于桌面端图标大小 |
| 手机端时钟字号 | `40px` | 随屏宽用 `clamp()` 自动收缩，超小屏（≤360px）再降一档 |
| 手机端标签名称字号 | `12px` | 与图标大小配合 |
| 手机端最多显示标签数量 | `0`（全部） | 标签很多时可只显示前 N 个，按添加顺序截取；横竖屏切换会自动重算 |

v0.2 起，手机端天气与日历小组件在混排网格中自动占满整行（`grid-column: 1 / -1`），标签仍按 `--mcols` 分列；拖动排序在触屏上同样可用。其它细节：统一左右边距保持齐平；搜索框输入字号固定 16px 以避免 iOS 聚焦时自动放大；背景随页面滚动（规避 iOS 上 `fixed` 背景抖动）；标签悬浮效果只在真有鼠标的设备启用。管理页自身也做了窄屏适配，可直接在手机上改配置。

## 背景设置（v0.2 独立子页面）

管理页「背景」子页面提供四种模式卡片，**选定一种后其余模式的详细设置自动置灰且不可编辑**（`filter: grayscale(1)` + 禁用控件）：

- **默认渐变**：使用系统内置渐变；
- **预设渐变**：5 套精选渐变方案（深蓝 / 紫粉 / 日落 / 薄荷 / 暗夜），一键切换；v0.2 修复了「选择预设渐变后首页变白」的问题（旧代码把渐变设好后又执行 `backgroundImage='none'` 抹掉了）；
- **自定义颜色**：两个十六进制颜色组成线性渐变（两色相同即纯色）；
- **背景图片**：3 张公开图床（picsum）预设图，或点击 / 拖拽上传（最大 8MB）、填 URL。上传区已重做为带图标与提示的拖拽区。

图片模式下可用**滑条 + 数值输入框**双向调节毛玻璃强度（`site.bgBlur`，0–40px），作用于时钟搜索框、天气与日历面板的 `backdrop-filter: blur()`。

## 预设图标（v0.2 本地化）

20 个常用图标已**保存到仓库本地** `public/icons/`（百度、Google、GitHub、B 站、YouTube、ChatGPT、DeepSeek、Claude、Gemini、Notion、Telegram、豆瓣、百度地图、CloudFlare、Docker、HomeAssistant、Vaultwarden、天气、immich、Netflix），管理页直接用 `/icons/xxx.png` 访问。

## 已发布镜像（v0.2）

本项目已接入 GitHub Actions：打 `v*` 标签或发布 Release 即自动构建并推送镜像，无需本地 Docker。`v0.2` 标签会产出 `0.2` 与 `latest` 两个 tag。

- **GitHub Container Registry**：`ghcr.io/fromeverywhere/onlytab:0.2`（同时打 `:latest`）
- **Docker Hub**：`fromeverywhere/onlytab:0.2`（同时打 `:latest`）
- 旧版 `v0.1` 镜像仍保留，可按需回退。

拉取运行（**务必挂载数据卷**，否则重建容器会丢配置）：

```bash
docker pull fromeverywhere/onlytab:0.2
docker run -d --name onlytab -p 3000:3000 --restart unless-stopped \
  -v /your/path/data:/app/data fromeverywhere/onlytab:0.2
```

> CI 通过 GitHub Secrets（`DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN`）推送 Docker Hub，凭据不入库、不明文。

### 绿联（UGREEN）NAS 构建示例

源码已构建运行于绿联 NAS，端口映射 `19321`：

```bash
cd /volume3/docker/build/onlytab
docker build -t onlytab:0.2 -t onlytab:latest .
docker run -d --name onlytab -p 19321:3000 --restart unless-stopped \
  -v /volume3/docker/build/onlytab/data:/app/data onlytab:0.2
# 浏览器访问 http://<绿联IP>:19321/
```

> NAS 上若原本的容器没有挂载数据卷，重建前先 `docker cp onlytab:/app/data ./data` 备份，再用上面的 `-v` 重建，配置就不会丢。
> 该 NAS 的 SFTP 子系统不可用、逐文件 SSH 命令容易触发连接重置，部署时建议把源码打成一个 tar.gz 经 SSH stdin 流式写入后解包。

## 资源占用

单个 Node 进程，无数据库、无外部中间件；空闲内存通常 **20~40 MB**，CPU 几乎为零。非常适合跑在 1C1G 甚至更小的轻量服务器 / NAS / 内网机。
